# AI Control Center — централизация AI на Нефтеюганск.инфо

## Аудит (фактическое состояние)

**11 AI-функций в облаке**, все через Lovable AI Gateway, ключ только на сервере (хорошо):
- `smart-search` — openai/gpt-6-astra через Responses API (AI SDK, стриминг)
- `ai-moderation`, `anti-fraud`, `listing-generator`, `price-advisor`, `banner-generator`, `promotion-advisor`, `trend-analyzer`, `seed-generator` — google/gemini-3-flash-preview через chat/completions (raw fetch)
- `csv-import`, `empty-category-detector` — без AI или смешанные

**Проблемы:**
1. Логика провайдера продублирована в 8 функциях (raw fetch, своя обработка ошибок, свой парсинг ответа)
2. Нет учёта использования: сколько запросов, сколько ошибок, сколько времени — нигде не пишется
3. Нет центральной конфигурации моделей — модель захардкожена в каждой функции
4. Нет версионирования промптов — промпты в коде
5. Нет лимитов и защиты от злоупотреблений (smart-search доступен анонимно без ограничений)
6. Нет единого админ-экрана: статистика разбросана, часть кнопок админки не сохраняет состояние

## Что строим (фаза 1 — фундамент)

### 1. Общий серверный AI-слой `supabase/functions/_shared/ai-service.ts`
- Центральная конфигурация: реестр модулей → модель по задаче, лимиты, таймауты
- Единая обработка ошибок шлюза (402/403/429/5xx по правилам семантики ошибок)
- Валидация входа (размеры, типы) и структурированного выхода (JSON-схема)
- Запись каждого вызова в журнал: модуль, модель, статус, длительность, ошибка
- Существующие модели НЕ меняем без одобрения — реестр отражает текущие

### 2. Таблицы в облаке (миграция)
- `ai_usage_log` — журнал вызовов (module, model, status, duration_ms, error, created_at); запись только с сервера, чтение только super_admin
- `ai_module_config` — конфигурация модулей (module, enabled, model, daily_limit, updated_by/at); чтение/запись только super_admin
- RLS на обеих, гранты по правилам public-схемы

### 3. Админ-функция `ai-control`
- Только для super_admin (проверка JWT + has_role)
- Отдаёт: список модулей с конфигурацией, статистику из ai_usage_log (запросы, успехи/ошибки, среднее время, последние ошибки, последний успех) — только реальные данные, без выдуманных метрик
- Позволяет включать/выключать модуль и менять лимит

### 4. Админ-страница `/admin/ai-control`
- Карточки модулей: статус (вкл/выкл), модель, запросы за 7/30 дней, % ошибок, среднее время, последняя ошибка
- Переключатель enabled, поле дневного лимита
- Без секретов — только «настроен/не настроен»

### 5. Пилот: перевести 2 функции на общий слой
- `ai-moderation` и `price-advisor` — через ai-service с журналированием
- Остальные 9 — в следующих фазах, чтобы не ломать работающее

### 6. Тесты
- Юнит-тесты реестра модулей и маппинга ошибок (vitest)
- Проверка в браузере: админ-страница под super_admin, реальные цифры после вызова price-advisor

## Следующие фазы (после одобрения фазы 1)
- Фаза 2: версионирование промптов (таблица ai_prompts, история, откат, активация)
- Фаза 3: лимиты по модулям (rate limiting в ai-service), дедупликация одинаковых запросов
- Фаза 4: перевод остальных 9 функций на общий слой
- Фаза 5: недостающие модули (SEO-помощник, рекомендации продавцу, отчёты)

## Ограничения
- Дизайн не трогаем, существующие модели не меняем, ключи остаются на сервере
- AI не выполняет SQL, не меняет роли, не делает деструктивных действий
